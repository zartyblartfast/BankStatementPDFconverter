# Confirmed-transfer reports

The four existing report keys and filenames are unchanged. `_query_all()` now returns `ReportRows` plus legacy statement dates; `ReportRows.policy` carries the shared movement snapshot. Each generator's `main()` remains the explicit file-writing entry point. Do not run these against the live report directory during QA.

## Data and arithmetic

`scripts/report_data.py::query_report` requires an explicit database path or connection. It borrows an existing caller transaction unchanged, otherwise owns only its read transaction. Rows use left joins, retain uncategorised/excluded transactions, original transaction fields, account IDs, notes, source paths and linked canonical document evidence. Active classifications and audit history are attached once per transaction. Revoked history is evidence, never active principal.

Shared `summarise_movement(..., include_excluded=False)` supplies raw and adjusted totals. Raw contains every selected row. Adjusted removes only active confirmed paired/unmatched principal and independently report-excluded rows. Categories never determine sign or principal. Credits are labelled cash credits (including refunds), not inferred income; debit movement retains fees and uncategorised rows.

Pence and IDs remain decimal strings in embedded JSON. The local `static/report-classic.js` sums, groups, formats and subtracts with BigInt, including amounts and IDs beyond Number's safe range. Only bounded relative chart/colour ratios become Numbers after exact aggregation; labels, tooltips and tables retain exact amounts. The familiar generator layouts/styles are reused: two summary donuts, source/category bar and donut charts, and the original statement-period heatmap. Income-source charts group by subcategory, not the parent category. The dashboard first applies its selected account and transaction-date scope; the original embedded From/To selectors further narrow the retained statement periods. Categories never classify principal or cash direction.

All inline payloads pass `script_json`. Local Chart.js is reused; no CDN dependency is added. Snapshot rebuilding is read-only; explicit single-row edits are separate authenticated user actions. Tables start at grouped category/source summaries. Expand a category and subcategory to see transactions and the existing Date/Merchant sorting controls. Transactions are created only on expansion, never as an auto-open raw list. Excluded rows and confirmed principal remain unchanged in ALL_TXNS and in a separate initially closed grouped section. Show excluded includes those original rows in the familiar charts/tables without mutating flags, notes or category assignments. Each expanded transaction retains note/category actions and source/account evidence.

## Integrated dashboard routes

Both routes are wired and verified on synthetic fixtures; the following contract is implemented:

1. In `/report` and `/report/raw/<name>`, resolve scope with `_dashboard_account_scope(conn)` and calendar filters with `_dashboard_period()`; return a validation response on error, including repeated selectors/invalid years. Do not use the old permissive period-filter path for new policy reports.
2. `selected, accounts = _dashboard_account_scope(conn)` returns selected ID or `None` and supported account dictionaries. Resolve IDs as `[selected]` if selected, otherwise `[a['account_id'] for a in accounts]`. Empty means no rows, never an implicit all-account fallback.
3. Wrapper render context additionally supplies `accounts=accounts` and `account_id=selected or ''`. `templates/report.html` preserves the existing period query and appends the literal account ID to the iframe query, including the empty selector. Its account select submits together with report and period controls.
4. Raw route calls `scripts.report_assets.serve_report_html(html, conn=conn, account_ids=resolved_ids, period=resolved_period, name=name)` while the explicit connection is open; return that string. The helper performs no file writes. For policy-stamped reports it rebuilds only the served response from a consistent current ledger snapshot, refreshing flags, classifications, scope totals and outside-counterpart/timing warnings.
5. Invalid account scopes and period contexts carrying errors raise ValueError instead of broadening. The route remains responsible for owned-GBP policy and query validation using the shared helpers. Unknown raw report keys retain existing 404 handling.

Raw serving additionally passes `legacy_all_accounts=selected is None`. Invalid/repeated selectors return HTTP 400. Missing raw report/key remains 404; missing ledger returns 409 without creating a database, while the wrapper remains available with empty account choices. Missing wrapper reports retain their existing redirect/message.

Legacy served reports are never stamped fresh based on timestamps or category hints. They receive an idempotent visible Regenerate warning. Exact-account records are filtered to the resolved IDs. Missing-account legacy records cannot match an explicitly selected account; the warned all-account compatibility view alone retains them when the resolved list is nonempty. This is not a verified owned-account snapshot. Missing dates cannot match bounded periods. Unchanged all-date payloads preserve old month evidence; filtered payloads derive months from retained rows. Assignment-looking note text is never rewritten as code. Bounded legacy views hide the old embedded date picker without a second JSON rewrite; `_apply_raw_report_period` remains available as a compatibility helper. Stored files are not rewritten. Unstamped builders use the same warned renderer.

## Safe inline editing

`static/report-actions.js` uses existing `ledgerFetch` from `static/report-client.js`: same-origin requests, session CSRF and same-origin credentials. Standalone editing is unsupported and visibly labelled even when scripts cannot load. Every expanded transaction row exposes Re-categorise and Edit note.

Re-categorise loads current `/api/categories` choices and submits exactly `txn_id`, `old_subcategory_id`, `category`, `subcategory` to `/api/search-recategorize`. No merchant expansion, definition creation, bulk scope or implicit Remember/rule write is available. Maps preserve literal prototype-like category names; untrusted text uses `textContent`/form values, never HTML. Cancel sends no mutation; failed choice loading leaves the dialog open and Save disabled.

IDs remain canonical decimal strings, validated in `1..9223372036854775807`, serialized as exact JSON integer tokens without JavaScript Number conversion. Notes use existing `/api/update-note` with one ID and optional `expected_note`. New dialogs provide the original note for atomic stale checking under `BEGIN IMMEDIATE`; legacy callers remain compatible. Existing trim/empty-to-NULL semantics remain, with a 10,000-character bound.

Successful commits remain `ok:true` if stored-report regeneration fails, with explicit saved warnings. Dialogs preserve warnings across reloading the same iframe URL; network/invalid-response failures say save outcome unknown, not falsely unsaved. Edits never change money, dates, source evidence or transfer decisions, and existing full-ledger fingerprints invalidate held transfer previews.

## Verification

`tests/test_transfer_reports.py` runs all four actual generator entry points with explicit scratch database/report constants and browser-opening mocks. `tests/report_classic_probe.js` executes actual generated inline code and the classic helper against a generated-element DOM/Chart boundary; it checks original donut/bar/heatmap elements, source grouping, closed/lazy grouped drilldown and expansion, raw/adjusted conservation, fees, exclusions, uncategorised rows, renamed/prototype-like categories, exact unsafe pence/IDs, literal notes and statement-period filters. `tests/test_classic_reports.py` specifically rejects the removed generic movementChart and flat drilldown. Additional tests cover borrowed snapshots, source identity, unmatched/revoked history, current served flags, empty/invalid scopes, wrapper query preservation and matching-scope shared-policy/AgentAnalysis aggregate parity. This is real Node execution, not a full visual-browser acceptance test.

`tests/test_transfer_report_routes.py` exercises actual Flask routes on all four scratch-generated reports: current-ledger flags, shared-policy scope parity, wrapper/iframe query preservation, invalid/repeated/empty scopes, missing resources and unchanged stored bytes. POST fixtures cover saved-refresh failure, stale/malformed/overflow note payloads, security guards, single-row category audit, preserved money/transfer/source fields and held-preview invalidation. Regeneration is mocked only for POST workflow/error tests; actual generation is exercised separately.

`tests/report_actions_probe.js` executes the real editing helper and `ledgerFetch` with DOM/network boundaries: prototype-like current choices, load failure, cancel, exact unsafe IDs, safe note values, same-origin/CSRF credentials, saved warnings, network uncertainty and standalone refusal. Node execution is not full visual-browser acceptance or a live-server rehearsal.

Use the app venv and, if needed, set TMPDIR to an existing isolated temporary directory. Protect original finance/config/PDF/CSV bytes before and after tests, and do not regenerate live stored reports, restart the live server, apply migration 004 or link real transactions as part of verification.
